1. Ce que la mise à jour v2.4.1 fait automatiquement

La mise à jour s'installe toute seule au démarrage de l'application (auto-update). Une fois installée, aucune manipulation technique de base de données n'est nécessaire : tout est intégré.

Accès rapide : ce guide est consultable à tout moment depuis le logiciel — Paramètres → bouton « Guide client » (en haut à droite). Lecture seule, sans risque de modification.

2. Les 5 étapes à faire sur chaque PC (une seule fois)

  1. Laisser la mise à jour s'installer. Ouvrir l'application, accepter la mise à jour si elle est proposée, puis laisser redémarrer. La migration de la base se fait toute seule au démarrage.
  2. Régler l'identifiant du poste de caisse (C1, C2, C3…). Voir section 3 — c'est l'intervention la plus importante.
  3. Lancer une synchronisation complète. Bouton de synchronisation → « Lancer la synchronisation maintenant ». Attendre la fin du bilan.
  4. Vérifier la matrice de convergence. Paramètres → Moniteur des postes : toutes les pastilles doivent être vertes, écarts à 0, file locale à 0.
  5. Ouvrir l'Assistant de cohérence. Paramètres → Assistant : lancer le scan, traiter les éventuels doublons « certains » et les écritures orphelines.
Pourquoi sur chaque PC ? L'identifiant du poste est un réglage local à chaque machine (il ne se synchronise pas). Il garantit des reçus uniques par caisse et une télémétrie lisible par poste. Un PC non réglé remonte sous son nom d'hôte (ex. FA606-PIQD835) au lieu de C3.

3. Régler l'identifiant du poste de caisse

Paramètres → section Imprimante Thermique / Poste → champ « Identifiant du Poste de Caisse (Multi-Postes) » → choisir la caisse correspondant à ce PC → enregistrer.

Règle d'or : deux PC ne doivent jamais porter le même code caisse. Le code est actif immédiatement et reste permanent sur ce PC. Il détermine la numérotation des reçus REC-ANNÉE-C<poste>-XXXXX et l'identité du poste dans le moniteur.

4. Lire la matrice de convergence

Paramètres → Moniteur des postes (réservé administrateur). Compare chaque PC au Cloud Supabase.

Les colonnes

ColonneSignification
Poste / Hôte-VersionCode caisse (C1…) + nom du PC + version de l'app.
État connexionConnecté vu il y a ≤ 10 min · Vu il y a X min/h · Hors-ligne > 24 h.
Élèves · Frais · Paiements · Caisse · Événements · Paiements év.Nombre de lignes actives locales. Pastille verte = égal au Cloud ; orange = écart, avec le delta affiché (ex. -3 = 3 de moins que le Cloud, +2 = 2 de plus).
File localeÉcritures en attente / bloquées / en quarantaine sur ce PC.
Statut convergenceSynchronisé si tous les comptes matchent et file à 0 ; sinon Écart.

Interpréter un écart

  • Delta négatif (local < Cloud) : ce PC n'a pas encore tout reçu → lancer une synchronisation complète. La parité automatique déclenche aussi un rattrapage (au plus une fois toutes les 6 h).
  • Delta positif (local > Cloud) : envois possiblement perdus/non confirmés → ouvrir l'Assistant / la file bloquée (section 5). Ne jamais forcer le statut « envoyé ».
  • Poste hors-ligne : normal si le PC est éteint ou sans internet. Les données restent en local et partiront à la reconnexion.
Limite à connaître : la matrice est une photo à la dernière synchronisation, pas un temps réel. Un PC éteint affiche son dernier bilan connu. Les compteurs mesurent le volume, pas la qualité ligne à ligne — d'où l'intérêt de l'Assistant.

5. Assistant de cohérence & file de synchronisation bloquée

Paramètres → Assistant de cohérence (administrateur). Regroupe le scan multi-classes, les doublons et la file bloquée.

a) Doublons « certains »

Le bouton « Unifier les certains » fusionne en un clic uniquement les doublons prouvés à 100 % (même élève, même paiement, mêmes montants). Les reçus papier déjà imprimés sont préservés. Les cas ambigus restent proposés au cas par cas avec preuve et niveau de confiance — vous décidez.

b) File bloquée / écritures orphelines

Une écriture « orpheline » = un paiement/caisse sans élève correspondant. Actions proposées :

ActionQuand l'utiliser
Rattacher à un élèveLe bon élève est suggéré ou retrouvé : le paiement lui est réattribué.
Créer l'élève manquantL'élève n'existe pas encore mais la fiche est connue.
Convertir en caisse généraleRecette réelle sans élève identifiable (ex. don, vente diverse).
ÉcarterÉcriture réellement invalide/doublon avéré. À utiliser avec prudence.
Interdictions absolues : ne jamais forcer une ligne en « envoyé/synced » ni purger la file pour faire disparaître un compteur d'erreur sans confirmation réelle du Cloud. Toute correction doit être prouvée, au cas par cas, et ne détruire aucune donnée. En cas de doute : ne pas écarter, demander de l'aide.

6. Alertes impayés

Le calcul est désormais unique et centralisé : la liste des impayés, la fiche de paiement de l'élève et le module finance utilisent exactement la même logique (même année scolaire, mêmes mois dus, même tarif résolu, seuil de solde, mois courant, élèves partis, cas Terminale).

Vérifié empiriquement : sur 790 élèves et 2365 mois dus, 329 mois signalés impayés — 0 faux positif, 0 écart avec la fiche, 0 alerte manquée. Si un mois apparaît impayé, c'est qu'aucun paiement correspondant n'existe en finance pour ce mois.

Un élève « enfant du personnel » est exonéré (tuition 0) : il n'apparaît pas en impayé. Les tarifs personnalisés (transport, uniformes, écolage) sont toujours préservés lors des synchronisations.

7. Reçus & clôture de caisse

Numérotation des reçus

Norme stricte par poste : REC-ANNÉE-C<poste>-XXXXX (ex. REC-2026-C3-00012). L'impression thermique 80 mm sort un double exemplaire (Parent + Caisse). Le compteur d'impressions distingue les reçus légalement imprimés.

Clôture de caisse

  • Journalière, par compte caissier ET par poste.
  • Une écriture « sans reçu » est rattachée au caissier qui l'a saisie.
  • La clôture consolidée « toutes stations » est une vue de synthèse, pas une clôture de poste.
Bonne pratique : clôturer chaque caisse en fin de journée sur son PC, après vérification que la file locale est à 0. Ne jamais clôturer pour « masquer » un écart : l'écart doit d'abord être expliqué via l'Assistant.

8. Automatique vs manuel

Automatique

  • Mise à jour de l'application au démarrage
  • Migration de la base (colonne deleted, année des événements)
  • Synchronisation toutes les 5 minutes + au démarrage
  • Rattrapage de convergence si manque local (toutes les 6 h max)
  • Préservation des tarifs & configurations personnalisées
  • Calcul unique des impayés

Manuel (client)

  • Régler le code poste une fois par PC
  • Lancer une sync complète après la mise à jour
  • Consulter la matrice / le moniteur
  • Traiter les doublons ambigus & orphelins dans l'Assistant
  • Clôture de caisse journalière par poste
  • Décider des cas financiers sensibles

9. Astuces & bonnes pratiques

  • Hors-ligne : tout continue de fonctionner. Les saisies sont enregistrées en local et partiront automatiquement à la reconnexion. Pas besoin d'attendre internet pour encaisser.
  • Un PC = un code caisse. Vérifiez le code après chaque réinstallation ou changement de PC.
  • Sync complète après mise à jour. Elle garantit que ce PC récupère tout le catalogue (événements, frais, paiements) avant de comparer.
  • Ne jamais forcer « synced » ni purger la file. Un compteur d'erreur est un signal, pas une gêne à masquer.
  • Préserver les reçus papier. En cas de doublon, on garde l'ancien reçu imprimé (keep-old) ; on ne réimprime pas par-dessus un reçu légal.
  • Pas de réinitialisation d'usine. Les axes de transport (ex. ambodivodava B, Tsilazaina), uniformes et tarifs personnalisés ne sont jamais écrasés.
  • Avant un appel au support : notez le code poste, la version, l'écart affiché et le message d'erreur exact — cela accélère le diagnostic.

11. Checklist de mise en service (par poste)

À cocher pour chaque PC (C1 à C5). Imprimable.

  • Mise à jour v2.4.1 installée et application redémarrée
  • Identifiant du poste de caisse réglé sur le bon code (Cx) — unique par PC
  • Synchronisation complète lancée et terminée
  • Matrice : toutes pastilles vertes, écarts à 0
  • File locale à 0 (attente / bloqués / quarantaine)
  • Assistant : scan lancé, doublons « certains » unifiés, orphelins traités
  • Impression test d'un reçu : bon code caisse dans le numéro
  • Clôture de caisse journalière effectuée par ce poste
Poste prêt. Répéter sur les 5 PC. En cas de blocage persistant après ces étapes, relever le code poste + version + message exact et contacter le support.
